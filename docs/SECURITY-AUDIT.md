# التدقيق الأمني للموقع والمستودع: الإصدار 2026.11.5

> **تحديث 5/11/2026:** نُفذت الإصلاحات بموافقتك، ما عدا الصفحتين الفارغتين في الطباعة وإعدادات الحسابات الخارجية. ما أُصلح وكيف اختُبر في `docs/SECURITY-FIXES-2026.11.5.md`. هذا الملف هو التدقيق الأصلي قبل الإصلاح.

**التاريخ:** 5/11/2026. **النطاق:**
- كود الموقع (`frontend/public`)؛
- إعدادات Netlify (`netlify.toml` و`_redirects` و`_headers`)؛
- مستودع GitHub وتاريخه (قراءة فقط)؛
- الموقع المنشور: طلبات قراءة GET عادية فقط، **بلا أي هجوم أو اختبار ضغط**؛
- خوادم Netlify محلية للاختبار الفعلي.

> **لا يوجد موقع آمن 100%.** غياب نتيجة في الفحص لا يعني غياب الثغرة. هذا التقرير يصف ما فُحص، وكيف، وما بقي خارج الفحص.

## ١. بنية الموقع الفعلية

تحققت منها أولًا، قبل افتراض أي شيء:

| العنصر | الواقع |
|---|---|
| الخادم | موقع ثابت (HTML وCSS وJS) على شبكة Netlify. **لا خادم تطبيق، ولا قاعدة بيانات، ولا Netlify Functions، ولا Edge Functions** |
| API | لا يوجد. كل طلبات الموقع قراءة ملفات عامة من الموقع نفسه: `professions.json` و`content/settings.json` و`data/occupation-dictionary.json` |
| النماذج | 8 نماذج: الحاسبة، والأهلية، والجاهزية، والتصديق، والبحث، ووافد، والاستعلام. **كلها تعمل داخل المتصفح ولا ترسل بيانات إلى خادم.** نتيجتها رابط واتساب أو طباعة |
| تسجيل الدخول | لا يوجد للزوار. **يوجد في Netlify نظام Identity مفعّل للوحة إدارة قديمة** (انظر عالي-١) |
| رفع الملفات | لا يوجد للزوار. لوحة الإدارة القديمة تسمح برفع صور إلى `images/uploads` لمن يملك حسابًا فيها |
| خدمات خارجية | Google Tag Manager (الرئيسية)، وFacebook Pixel، وخرائط OpenStreetMap وLeaflet، وخطوط Google (محلية)، وواتساب |

**ما لا ينطبق على هذا الموقع** لغياب المكوّن نفسه، وأثبت ذلك الفحص:
- **لا ينطبق:**
  - SQL Injection؛
  - SSRF؛
  - Remote Code Execution؛
  - IDOR والوصول إلى بيانات عملاء آخرين (لا بيانات عملاء مخزنة)؛
  - CSRF (لا يوجد طلب يغيّر حالة على الخادم)؛
  - إدارة الجلسات للزوار.
- **هذه الأنواع تظهر فورًا إن أُضيفت لاحقًا** وظيفة خلفية أو قاعدة بيانات أو API، وتحتاج حينها تدقيقًا جديدًا.

## ٢. النتائج حسب الخطورة

### عالٍ (High)

#### عالي-١: لوحة إدارة قديمة (Decap CMS) مفعّلة على الموقع الحي وتكتب مباشرة على `main`

- **المكان:** `frontend/public/admin-secure/` (`index.html` و`config.yml`) + Netlify Identity + Git Gateway.
- **ما وجدته على الموقع الحي** (طلبات قراءة فقط):
  - `/.netlify/identity/settings` يجيب: Identity **مفعّل**، والدخول بالبريد وكلمة المرور، والتسجيل العام **مغلق** (`disable_signup: true`).
  - `/.netlify/git/github` يجيب **401**، أي أن Git Gateway مفعّل ويطلب رمز دخول.
  - `/admin-secure/` و`/admin-secure/config.yml` متاحان للعموم. الإعداد: `backend: git-gateway`، `branch: main`، `media_folder: images/uploads`.
  - فرع `main` **غير محمي** على GitHub.
- **الاستغلال النظري:** أي حساب دُعي سابقًا إلى Identity يكفي: كلمة مرور ضعيفة أو مسربة، أو تصيّد. بالحساب يمكن:
  - تعديل `content/settings.json`: يقرؤه الموقع ليعرض **رقم واتساب والهاتف والبريد في كل الصفحات**، فيُحوَّل العملاء إلى رقم المهاجم؛
  - كتابة مقال Markdown يُعرض بلا تنقية في `blog-post.html` (XSS مخزّن)؛
  - رفع ملفات إلى `images/uploads`.
- **الأثر:** تشويه الموقع، وتحويل تواصل العملاء، ونشر فوري لأي تعديل لأنه على `main`.
- **ملاحظة:** قررت سابقًا «لا تفعّل Netlify Identity ولا لوحة إدارة». الفحص يُظهر أنها **مفعّلة الآن في لوحة Netlify** من إعداد سابق.
- **الإصلاح المقترح (يحتاج موافقتك):**
  1. **في لوحة Netlify (أنت):**
     - Site configuration ← Identity ← Services ← **Git Gateway: Disable**؛
     - Identity ← Users: راجع الحسابات واحذف غير المعروفة؛
     - ثم **Disable Identity**.
  2. **في المستودع (أنا):**
     - حذف `frontend/public/admin-secure/`؛
     - حذف `identity.netlify.com` و`unpkg.com` و`api.github.com` من CSP؛
     - إضافة تحويل `/admin-secure/*` ← 404.
     - **تبقى `content/settings.json`،** فالموقع يقرؤها.
  3. **في GitHub (أنت):** حماية فرع `main` (انظر §٤).
- **الاختبار بعد الإصلاح:**
  - `/admin-secure/` يعطي 404؛
  - `/.netlify/identity/settings` يعطي 404 بعد التعطيل؛
  - لا مخالفات CSP في فحص الصحة.

### متوسط (Medium)

#### متوسط-١: نافذة طباعة المهنة لا تُهرّب ثلاث قيم (XSS بنقرة)

- **المكان:** `frontend/public/script.js`، الدالة `printProfessionDocument`: `${professionName}` و`${printNationality}` و`${req}` تُكتب بـ`document.write` دون تهريب. الملاحظة وحدها مهرّبة (`escP`).
- **الاستغلال النظري:**
  - رابط مثل `/professions.html?search=<كود>` يملأ صندوق البحث؛
  - المهنة غير موجودة، فيقترح `smart-fallback.js` قائمة تقديرية بالاسم المكتوب؛
  - عند ضغط الزائر «طباعة» يُنفَّذ الكود في نطاق الموقع. الشيء نفسه في خانة «جنسية أخرى».
- **مؤكَّد بالاختبار:** `tests/print-escape-probe.mjs` على خادم محلي. الحمولة البريئة (`window.__x=1`) نُفذت في الحالات الثلاث.
- **الأثر:** محدود، فلا حسابات ولا جلسات ولا دفع. لكن يمكن عرض محتوى مزيف (رقم واتساب أو نموذج) تحت نطاق موقعك الحقيقي.
- **الإصلاح المقترح:**
  - تهريب القيم الثلاث بالدالة نفسها `escP`؛
  - تحققت أن بيانات المهن لا تحوي أي HTML مقصود (0 بند فيه `<` أو `>`)، **فشكل الطباعة لن يتغير.**
  - يحتاج موافقتك لأنه داخل نظام الطباعة المعتمد.
- **الاختبار بعد الإصلاح:**
  - `print-escape-probe` يجب أن ينجح؛
  - طباعة كل المهن الـ1,102 في Chrome وEdge يجب أن تبقى 832 صفحة واحدة و270 صفحتين، بلا مشاكل.

#### متوسط-٢: سياسة CSP أوسع من اللازم

- **المكان:** `frontend/public/_headers`.
- **ما وجدته:**
  - `script-src` فيه `'unsafe-inline'` و`'unsafe-eval'`، ومصادر عامة كاملة: `https://unpkg.com` و`https://cdn.jsdelivr.net`، أي **أي حزمة npm**.
  - مصادر غير مستخدمة إطلاقًا: `cdn.tailwindcss.com` و`static.prod-images.emergentagent.com` و`api.github.com`، و`identity.netlify.com` (للوحة القديمة فقط).
  - `img-src https:` يسمح بأي مصدر.
- **الاستغلال النظري:** إن وُجد خلل XSS (مثل متوسط-١)، تسمح السياسة الحالية بتحميل أي كود من unpkg أو jsdelivr وتنفيذه.
- **الإصلاح المقترح:**
  - حذف المصادر غير المستخدمة؛
  - حذف `'unsafe-eval'`: لا يوجد `eval` في كود الموقع؛
  - تقييد jsdelivr بمسار المكتبة المحددة أو استضافتها داخل الموقع؛
  - إبقاء `'unsafe-inline'` الآن: في الصفحات 8 سكربتات و14 معالج أحداث داخل HTML. إزالتها خطوة لاحقة، بنقلها إلى ملفات.
- **الاختبار بعد الإصلاح:** فحص الصحة (134 صفحة) بلا أي مخالفة CSP، والطباعة وPWA والخرائط تعمل.

#### متوسط-٣: مكتبات من CDN بإصدار غير مثبت وبلا SRI

- **المكان:**
  - `blog-post.html` يحمّل `cdn.jsdelivr.net/npm/marked/marked.min.js` (**آخر إصدار دائمًا**) و`js-yaml@4`؛
  - `leaflet-map.js` يحمّل Leaflet 1.9.4 من cdnjs بلا `integrity`؛
  - اللوحة القديمة تحمّل `decap-cms@^3.0.0`.
- **الاستغلال النظري:** اختراق حزمة أو CDN (سلسلة توريد) يحقن كودًا في موقعك تلقائيًا.
- **الإصلاح المقترح:**
  - `blog-post.html` قالب قديم بلا روابط إليه، عليه noindex، يعرض Markdown بلا تنقية. **أقترح حذفه** مع `content/blog`؛
  - أو تثبيت الإصدار وإضافة SRI وDOMPurify إن أردت إبقاءه؛
  - Leaflet: إضافة `integrity` أو استضافته داخل الموقع.

#### متوسط-٤: صلاحيات المستودع

- `main` **غير محمي** (تحققت من واجهة GitHub العامة). أي حساب له صلاحية كتابة، أو تطبيق مرتبط، يدفع إليه مباشرة، فيُنشر فورًا على Netlify.
- **فروع قديمة:**
  - `conflict_110426_1628`: commits آلية من أداة سابقة في 11/4/2026؛
  - `staging-dev`: نفس commit الفرع `main`.
- **لا GitHub Actions.**
- **الإصلاح:** في §٤، إعدادات تنفذها أنت.

### معلومات (Informational)

- **`X-XSS-Protection: 1; mode=block`:** رأس متروك في المتصفحات الحديثة. لا ضرر، ويمكن جعله `0`.
- **HSTS مع `preload` و`includeSubDomains`:** صحيح، بشرط أن تعمل كل النطاقات الفرعية بـHTTPS.
- **رؤوس الأمان موجودة على كل أنواع الردود** (الصفحة، وJS، وJSON، وTXT، و404): HSTS، وCSP، وX-Frame-Options، وnosniff، وReferrer-Policy، وPermissions-Policy.
- **الإغراق والروبوتات:**
  - الموقع ثابت على شبكة Netlify، ولا وظائف خلفية يُستنزف موردها. الخطر المتبقي هو استهلاك حصة النقل (bandwidth).
  - **أقترح:** تنبيهات الاستخدام في Netlify (Usage & billing). حماية DDoS الأساسية من Netlify نفسها.
  - **Cloudflare WAF وRate Limiting** تحتاج نقل DNS، وبعضها مدفوع، **فلم أقترح تنفيذها دون موافقتك.**
  - **لم يُجرَ أي اختبار ضغط.**
- **OWASP ZAP:** غير مثبت على هذا الجهاز، وتنزيله يحتاج موافقتك. بديلًا عنه أجريت اختبارات مكافئة مكتوبة ومحفوظة (§٣).

## ٤. إعدادات GitHub وNetlify (تنفذها أنت: لا أملك صلاحية عليها)

### GitHub (`injazksa/SAUDIA1010`)

1. **Settings ← Branches ← Add rule لـ`main`:**
   - Require a pull request before merging؛
   - منع الدفع المباشر و`force push`.
2. **Settings ← Code security:**
   - **Secret scanning** و**Push protection**: Enable؛
   - Dependabot alerts: Enable.
3. **Settings ← Collaborators:** راجع من له صلاحية كتابة، واحذف غير المعروف.
4. **Settings ← Deploy keys و Integrations ← GitHub Apps:**
   - تأكد أن تطبيق Netlify وحده مرتبط؛
   - احذف أي تطبيق لأداة سابقة، مثل الأداة التي أنشأت `.emergent` وcommits «auto-commit».
5. **حسابك:** فعّل المصادقة الثنائية (2FA).
6. **الفروع القديمة:** `conflict_110426_1628` و`staging-dev`. احذفهما إن لم تكونا مستخدمتين. لن أحذفهما.

### Netlify

1. **Identity:** عطّل Git Gateway، وراجع المستخدمين، ثم عطّل Identity (عالي-١).
2. **Team ← Members:** راجع الأعضاء، وفعّل 2FA لكل حساب.
3. **Site configuration ← Build & deploy:**
   - **Deploy Previews:** للمستودع العام، اجعل نشر طلبات الـFork يتطلب موافقة، أو عطّله؛
   - Branch deploys: الفرع `main` فقط، إن لم تستخدم `staging-dev`.
4. **Environment variables:** لا يوجد ما يحتاجه الموقع. إن وُجدت متغيرات قديمة غير مستخدمة فاحذفها.
5. **Build hooks:** إن وُجد رابط Build hook قديم فاحذفه، فمن يملكه يستطيع تشغيل النشر.
6. **Forms:** الموقع لا يستخدم Netlify Forms. يمكن تعطيل «Form detection».
7. **Usage alerts:** فعّل تنبيه استهلاك النقل.

## ٦. ما لم يُفحص

- **لوحتا Netlify وGitHub من الداخل:** الأعضاء، والمستخدمون، والتطبيقات، والمتغيرات، وBuild hooks. لا صلاحية لي عليها.
- **Cloudflare / DNS:** لا يُستخدم حاليًا.
- **اختبار الاختراق اليدوي العميق واختبارات الضغط:** لم تُجرَ. والفحص الآلي لا يغني عنها.
