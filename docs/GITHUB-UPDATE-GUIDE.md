# دليل تحديث مستودع GitHub بأمان

**الفكرة:** لا نلمس الفرع الرئيسي `main` مباشرة.
1. نحفظ النسخة الحالية بعلامة (tag)، فيمكن الرجوع إليها دائمًا.
2. نضع الإصدار في **فرع جديد**.
3. نراجعه على Netlify كنشر تجريبي (Deploy Preview).
4. ندمجه في `main` بعد الموافقة فقط.

> ⚠️ **لا تستخدم رفع الملفات من موقع GitHub.** يقبل 100 ملف فقط في كل مرة، ولا يحذف الملفات القديمة. الإصدار فيه 1,410 ملفًا، ويجب حذف 1,616 ملفًا قديمًا. استخدم **GitHub Desktop** (الطريقة أ) أو **git** (الطريقة ب).

## ما الذي سيتغيّر في المستودع

- **الإصدار يحلّ محل محتوى المستودع بالكامل.** لذلك نحذف القديم كله (عدا مجلد `.git`)، ثم ننسخ الإصدار. هكذا لا تبقى نسختان متعارضتان من أي ملف.
- **القائمة الكاملة** ملفًا ملفًا، مع سبب حذف كل ملف: `docs/compare-files.csv`. الملخص في `docs/COMPARE-WITH-GITHUB.md`.

| الحالة | العدد |
|---|---|
| ملفات جديدة | 355 |
| ملفات معدّلة | 1,019 |
| بلا تغيير | 34 |
| تُحذف من المستودع | 1,616 |

- **ما يُحذف:** لم يكن Netlify يقرؤه أصلًا، ولا يراه الزوار:
  - نسخة مكررة من الموقع في جذر المستودع؛
  - تطبيق React قديم، وخادم Python؛
  - `_headers` و`_redirects` و`.htaccess` قديمة في الجذر؛
  - ملفات أدوات سابقة.
  - **داخل الموقع نفسه:** ملفات أُعيدت تسميتها ولها تحويل 301، وملفات الذكاء الاصطناعي القديمة (تتحول 301 إلى `/llms.txt`).
- **ما يبقى من الإعدادات:**
  - `netlify.toml` في الجذر؛
  - `frontend/public/_redirects` و`frontend/public/_headers`.
  - كلها في الإصدار بنسختها المحدّثة.
- **ربط Netlify لا يتغيّر:** المستودع والفرع ومجلد النشر كما هي. لا متغيرات بيئة ولا أسرار. التفصيل في `docs/NETLIFY-GUIDE.md`.
- **حماية فهرسة Google:**
  - كل رابط قديم كان موجودًا يتحول بـ301 واحد إلى صفحته الجديدة؛
  - خريطة الموقع فيها الصفحات النهائية فقط.
  - التفصيل في `docs/TEST-REPORT.md` §٥.

## قبل البدء

- **ثبّت GitHub Desktop** من https://desktop.github.com، وسجّل الدخول بحسابك. يتضمن git، فيكفي للطريقتين.
- فك ضغط `saudia-visa-release-2026-11-05.zip` في مجلد مستقل، مثلًا `C:\release`:
  - زر يمين ← **استخراج الكل** (Extract All)، أو 7-Zip.
  - **لا تستخدم أمر `tar`**، فهو لا يقرأ الأسماء العربية.
- **تأكد أن `netlify.toml` في أول المجلد مباشرة**، لا داخل مجلد فرعي.
- أبقِ ZIP النسخة السابقة (`previous-version-SAUDIA1010-main.zip`) محفوظًا.

## الطريقة أ: GitHub Desktop (بلا أوامر)

1. **افتح المستودع:**
   - افتح GitHub Desktop.
   - **File ← Clone repository**، واختر المستودع.
   - انتظر التنزيل.
2. **احفظ النسخة الحالية:**
   - **History**، ثم آخر commit.
   - زر يمين ← **Create tag…**
   - الاسم: `before-2026.11.5`.
3. **أنشئ فرعًا جديدًا:**
   - **Current branch ← New branch**.
   - الاسم: `release-2026.11.5`، مبنيًا على `main`.
4. **احذف محتوى المستودع القديم:**
   - **Repository ← Show in Explorer**.
   - احذف **كل شيء ما عدا مجلد `.git`** (مجلد مخفي: فعّل «إظهار العناصر المخفية» في مستكشف Windows).
5. **انسخ محتوى الإصدار:**
   - من `C:\release` إلى مجلد المستودع، بما فيه الملف المخفي `.gitignore`.
6. **ارجع إلى GitHub Desktop:**
   - ستظهر التغييرات: ملفات محذوفة وجديدة ومعدّلة.
   - اكتب في Summary: `Release 2026.11.5`.
   - اضغط **Commit to release-2026.11.5**.
7. **ارفع الفرع:**
   - اضغط **Publish branch**، ثم **Push origin** للعلامة إن طُلب.
8. **افتح Pull Request:**
   - **Branch ← Create pull request**.
   - في GitHub: من `release-2026.11.5` إلى `main`.
   - **لا تدمج بعد.**
9. **راجع النشر التجريبي:** Netlify ينشئ Deploy Preview للطلب تلقائيًا. افحصه وفق `docs/NETLIFY-GUIDE.md` §3.
10. **عند الموافقة:**
    - **Merge pull request**؛
    - Netlify ينشر على الموقع الحقيقي.

## الطريقة ب: git (أوامر)

في PowerShell. ضع رابط مستودعك بدل `<رابط-المستودع>`:

```bash
git clone <رابط-المستودع> saudia-repo
```

```bash
cd saudia-repo
```

احفظ النسخة الحالية بعلامة، وارفعها:

```bash
git tag before-2026.11.5
```

```bash
git push origin before-2026.11.5
```

أنشئ الفرع الجديد:

```bash
git checkout -b release-2026.11.5
```

احذف كل الملفات المتتبَّعة. مجلد `.git` يبقى:

```bash
git rm -r -q .
```

انسخ الإصدار إلى المستودع:

```bash
Copy-Item -Path C:\release\* -Destination . -Recurse -Force
```

```bash
Copy-Item -Path C:\release\.gitignore -Destination . -Force
```

راجع التغييرات، ثم احفظها وارفعها:

```bash
git add -A
```

```bash
git status --short | Measure-Object
```

```bash
git commit -m "Release 2026.11.5"
```

```bash
git push -u origin release-2026.11.5
```

ثم افتح Pull Request على GitHub، من `release-2026.11.5` إلى `main`، وتابع من الخطوة 9 أعلاه.
