# دليل حماية GitHub وNetlify: خطوات تنفذها أنت

**لم أنفذ أيًا من هذه الخطوات:** لا أملك تسجيل دخول إلى حسابك في GitHub ولا في Netlify. كل ما يلي تعليمات فقط، وكل قرار فيها لك.

**الترتيب المقترح:**
1. Netlify، الجزء أ (يغلق أخطر ثغرة)؛
2. GitHub، الجزء ب (من يملك صلاحية الكتابة)؛
3. حماية `main`؛
4. فحص الأسرار؛
5. الباقي.

---

## أ. Netlify: إغلاق لوحة الإدارة القديمة نهائيًا

حذفت ملفات اللوحة (`admin-secure`) من نسخة التطوير. لكن **الخدمتين ما زالتا مفعّلتين في حساب Netlify** على الموقع الحي:
- `/.netlify/identity/settings` يجيب بأن Identity مفعّل؛
- `/.netlify/git/github` يجيب 401، أي أن Git Gateway يعمل.

**الحذف من المستودع وحده لا يوقفهما.** لذلك:

1. ادخل [app.netlify.com](https://app.netlify.com) ← اختر موقع `saudia-visa.com`.
2. **Site configuration ← Identity:**
   - افتح **Users**: هذه الحسابات تستطيع الدخول إلى اللوحة القديمة والكتابة على `main` عبر Git Gateway. **دوّن أسماءها، ثم احذف كل حساب**، فلا أحد يحتاجها بعد الآن.
   - **Services ← Git Gateway:** اضغط **Disable**. يتوقف فورًا أي تعديل للمستودع عن طريق الموقع.
   - **Registration:** تأكد أنها **Invite only**. هي كذلك حاليًا.
   - **Disable Identity** (أسفل الصفحة): يحذف Identity وحساباته. لا وظيفة أخرى في الموقع تعتمد عليه، وتحققت من ذلك بالبحث في كل ملفات الموقع.
3. **بعد ذلك، تحقق بنفسك:** افتح `https://saudia-visa.com/.netlify/identity/settings`. يجب أن يعطي «Not Found» بدل بيانات الإعداد.

**متى؟** لا يضر الموقع الحالي إطلاقًا: اللوحة غير مستخدمة. ويمكن تنفيذه قبل رفع الإصدار الجديد.

## ب. GitHub: من يملك صلاحية الكتابة على المستودع

**ما وجدته في سجل المستودع العام:**

| الحساب أو الأداة | ماذا كتب | متى |
|---|---|---|
| `CJWTRUST` (بريد `@manus.im`، أداة Manus) | commit «SEO & AI Enhancement…» على `main` | 10/7/2026 |
| `emergent-agent-e1` (أداة Emergent) | 11 commit على الفرع `conflict_110426_1628` | أبريل 2026 |
| حسابك `injazksa` | باقي التحديثات | يونيو–أغسطس 2026 |

**أي أداة كتبت في المستودع قد تكون صلاحيتها ما زالت قائمة.** راجع الأماكن الأربعة (لا يظهر أي منها إلا لك بعد تسجيل الدخول):

1. **المتعاونون:** المستودع ← **Settings ← Collaborators**. احذف أي حساب غير معروف، مثل `CJWTRUST`، إن ظهر.
2. **تطبيقات GitHub المثبتة:** صورة حسابك ← **Settings ← Applications ← Installed GitHub Apps**.
   - **أبقِ Netlify** (هو الذي ينشر الموقع).
   - أزل أي أداة لم تعد تستخدمها (Manus، Emergent وغيرهما)، أو قيّدها بمستودعات محددة (**Configure ← Repository access**).
3. **التطبيقات المأذون لها (OAuth):** **Settings ← Applications ← Authorized OAuth Apps**. اضغط **Revoke** لكل أداة لا تعرفها أو لم تعد تستخدمها.
4. **مفاتيح الوصول:**
   - **Settings ← Developer settings ← Personal access tokens:** احذف أي مفتاح قديم لا تعرف استخدامه.
   - وفي المستودع: **Settings ← Deploy keys**، ثم **Settings ← Webhooks**. أبقِ ما يخص Netlify فقط.

> لا تحذف ارتباط Netlify بالمستودع: عليه يعتمد نشر الموقع.

## ج. حماية فرع `main` (Ruleset)

**الحالة اليوم:** لا توجد أي قاعدة على `main`. أي حساب له صلاحية كتابة يدفع إليه مباشرة، فيُنشر فورًا.

المستودع عام وتملكه أنت وحدك، فالقواعد التالية **مجانية**:

1. المستودع ← **Settings ← Rules ← Rulesets ← New ruleset ← New branch ruleset**.
2. **الاسم:** `protect-main`. **Enforcement status:** Active.
3. **Target branches ← Add target ← Include default branch** (`main`).
4. **Bypass list:** أضف **Repository admin** (أنت). بدونه لا تستطيع دمج طلباتك بنفسك، لأنك المراجع الوحيد.
5. فعّل:
   - ✅ **Restrict deletions:** يمنع حذف `main`.
   - ✅ **Block force pushes:** يمنع مسح التاريخ.
   - ✅ **Require a pull request before merging**:
     - **Required approvals: 0** لأنك تعمل وحدك. تبقى الفائدة: كل تغيير يمرّ بطلب دمج تراه، وNetlify ينشئ له معاينة قبل النشر؛
     - إن أضفت مطورًا آخر لاحقًا، اجعلها 1.
   - (اختياري) **Require linear history**.
6. **Create**.

**بعد الحماية:** الدفع المباشر إلى `main` يُرفض، والطريقة الوحيدة هي فرع، ثم Pull Request، ثم دمج. هذا ما يصفه `docs/GITHUB-UPDATE-GUIDE.md`.

**الفرعان القديمان:**
- `conflict_110426_1628` (من أداة Emergent)؛
- `staging-dev` (نسخة مطابقة لـ`main`).

إن لم تستخدمهما فاحذفهما من **Branches**. **قبل حذف `staging-dev`** تأكد في Netlify (Site configuration ← Build & deploy ← Branches) أنه ليس فرع نشر.

## د. فحص الأسرار (Secret Scanning)

**للمستودعات العامة مجاني:**

1. **Settings ← Advanced Security** (أو **Code security**).
2. **Secret Protection / Secret scanning: Enable**، ثم **Push protection: Enable**. يرفض GitHub أي دفع فيه مفتاح أو كلمة مرور قبل أن يصل.
3. **Dependabot alerts: Enable**. الموقع بلا حزم اليوم، لكنه ينبّهك إن أُضيفت لاحقًا.

بعدها يفحص GitHub **كل تاريخ المستودع**، وهو ما لم أستطع فحصه كاملًا من الخارج. لم أجد أي سر في 1,720 ملفًا متاحًا. إن ظهر تنبيه:
- **لا يكفي حذف الملف.** أبطل المفتاح نفسه عند الجهة التي أصدرته، ثم أنشئ مفتاحًا جديدًا.

## هـ. Netlify: إعدادات أخرى

| الإعداد | المكان | التوصية |
|---|---|---|
| أعضاء الفريق | Team ← Members | راجع من له دخول، واحذف غير المعروف |
| نشر طلبات الدمج من نسخ الآخرين (Forks) | Site configuration ← Build & deploy ← Deploy Previews | المستودع عام: اجعل معاينة طلبات الـFork تحتاج موافقة، أو عطّلها |
| فروع النشر | Build & deploy ← Branches | `main` فقط، إلا إن كنت تستخدم `staging-dev` |
| Build hooks | Build & deploy ← Build hooks | احذف أي رابط قديم: من يملكه يستطيع تشغيل نشر |
| متغيرات البيئة | Site configuration ← Environment variables | الموقع لا يحتاج أي متغير. احذف القديم غير المستخدم |
| Forms | Forms | الموقع لا يستخدم نماذج Netlify. يمكن تعطيل «Form detection» |
| تنبيهات الاستهلاك | Team ← Usage & billing | فعّل تنبيه حصة النقل (حماية من الاستنزاف). **لا يحتاج اشتراكًا** |

**لا تغيّر:** النطاق، وDNS، ومجلد النشر، وأمر البناء.

## و. المصادقة الثنائية (2FA): للمعرفة فقط، والقرار لك

**لن أفعّلها، ولن أطلب منك أي رمز أو تغيير في وسائل الاسترداد.** هذا شرح لتقرر بنفسك.

**مخاطر عدم تفعيلها:**
- كلمة المرور وحدها تحمي حسابي GitHub وNetlify. إن تسرّبت (تصيّد، أو تكرار نفس كلمة المرور في موقع آخر اختُرق)، يستطيع صاحبها:
  - تعديل المستودع والدمج في `main`، فيتغير الموقع الحي، ومنه أرقام واتساب والهاتف التي يتواصل بها عملاؤك؛
  - حذف المستودع أو تغيير ربط Netlify أو النطاق.
- **حماية الفرع (ج) لا تمنع صاحب الحساب نفسه:** من يدخل بحسابك يملك صلاحياتك كلها.
- **ملاحظة:** GitHub يطلب 2FA تدريجيًا من الحسابات التي تكتب كودًا، وقد يطلبه منك يومًا تلقائيًا.

**الخيارات إن قررت لاحقًا** (Settings ← Password and authentication):

| الطريقة | الأمان | ملاحظة |
|---|---|---|
| Passkey (بصمة الجهاز أو Windows Hello) | الأعلى | الأسهل استخدامًا |
| مفتاح أمان مادي (YubiKey) | الأعلى | يحتاج شراء مفتاح |
| تطبيق مصادقة (Microsoft/Google Authenticator) | عالٍ | مجاني على الهاتف |
| رسائل SMS | أقل | عرضة لاختطاف الرقم. الأفضل كوسيلة احتياطية فقط |

**الاسترداد** (أهم خطوة عند التفعيل):
- GitHub يعطيك **رموز استرداد** (Recovery codes). احفظها خارج الهاتف: ورقة في مكان آمن، أو مدير كلمات مرور. بدونها، فقدان الهاتف قد يعني فقدان الحساب.
- أضف **وسيلتين على الأقل** (مثلًا Passkey وتطبيق مصادقة)، حتى تبقى إحداهما إن ضاعت الأخرى.
- في Netlify: الطريقة نفسها من **User settings ← Security**، مع حفظ رموز الاسترداد.
